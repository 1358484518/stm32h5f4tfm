使用环境 ubuntu22.04

说明：本文是早期环境搭建笔记。当前仓库是 STM32H5F4（分支 stm32h5f4）。
编译 SPE 用仓库根目录 ./buildtfm.sh；烧录用 ./flash_stm32h5f4.sh 或 windows-tfm-tools。
自己编的未签名 bin 用 tfmmakeproject/sign_kit 或 CubeIDE 的 sign_kit 签名。
NS 工程里已删除 TFM_UPDATE.sh / regression.sh。完整步骤见仓库根目录 readme.md。

1.安装依赖
	sudo apt-get update
	sudo apt-get install -y git curl wget cmake ninja-build build-essential \
		libssl-dev python3 python3-venv python3-pip

2. 安装官方 ARM GNU 工具链 使用版本14.3.1
	下载地址：
	https://developer.arm.com/downloads/-/arm-gnu-toolchain-downloads

3.安装编译器设定编译器路径
	export PATH=/home/lubancat/test/tfm/arm-gnu-toolchain-14.3.rel1-x86_64-arm-none-eabi/bin:$PATH
	
4.下载tfm固件
	git clone https://git.trustedfirmware.org/TF-M/trusted-firmware-m.git
	cd trusted-firmware-m/
	git fetch --tags
	git checkout TF-Mv2.3.0
	git describe --tags
	
5.下载tfm-test固件
	cd ..
	git clone https://git.trustedfirmware.org/TF-M/tf-m-tests.git
	cd tf-m-tests/
	git fetch --tags
	git checkout TF-Mv2.3.0
	git describe --tags
	cd ..

6. 安装 Python 依赖
	cd trusted-firmware-m
	python3 -m venv .venv
	source .venv/bin/activate
	pip install --upgrade pip setuptools wheel	
	pip install -e .
	
	source .venv/bin/activate
	
	rm -rf build_s
	
	cmake -S ../tf-m-tests/tests_reg/spe \
	-B build_s \
	-GNinja \
	-DTFM_PLATFORM=stm/stm32h573i_dk \
	-DTFM_TOOLCHAIN_FILE=$PWD/toolchain_GNUARM.cmake \
	-DCONFIG_TFM_SOURCE_PATH=$PWD \
	-DTFM_PSA_API=ON \
	-DTFM_ISOLATION_LEVEL=1 \
	-DTEST_S=ON \
	-DTEST_NS=ON

	git config --global user.email "1358484518@qq.com"
	git config --global user.name "klp"
		
	ninja -C build_s install -j$(nproc)

7.非安全侧编译
	注意：保持命令行窗口在 trusted-firmware-m 目录
	
7.1	清理旧构建（可选）
	rm -rf build_ns
	
7.2 配置
	cmake -S ../tf-m-tests/tests_reg \
	-B build_ns \
	-GNinja \
	-DCONFIG_SPE_PATH=$PWD/build_s/api_ns \
	-DTFM_TOOLCHAIN_FILE=$PWD/build_s/api_ns/cmake/toolchain_ns_GNUARM.cmake
	
7.3 编译
	ninja -C build_ns -j$(nproc)

9.烧录步骤
	参考文档：
	https://trustedfirmware-m.readthedocs.io/en/latest/platform/stm/stm32h573i_dk/readme.html
	https://github.com/TrustedFirmware-M/trusted-firmware-m/tree/main/docs/platform/stm/stm32h573i_dk
	
	在构建文件夹/home/klp/test/tfmwork/trusted-firmware-m/platform/ext/target/stm/common/scripts中：
	postbuild.sh根据 flash_layout.h 更新 regression.sh 和 TFM_UPDATE.sh 脚本
	regression.sh设置平台选项字节配置并擦除平台
	TFM_UPDATE.sh将 bl2、安全和非安全镜像写入目标磁盘
	将开发板连接到 USB 接口，并按以下顺序执行 3 个脚本以更新平台：postbuild.sh、regression.sh、TFM_UPDATE.sh
	
	注意1：烧录最好不要使用 STM32CubeProgrammer ，如果要使用STM32CubeProgrammer需要使用命令行启动
	/STMicroelectronics/STM32Cube/STM32CubeProgrammer/bin$ ./STM32CubeProgrammer
	一定要在 .bashrc 设置好编程软件的路径：export PATH="$PATH:/home/klp/STMicroelectronics/STM32Cube/STM32CubeProgrammer/bin"

	注意2：烧录前的py环境必须要在命令行设置：
		cd /home/klp/test/tfmwork/trusted-firmware-m
		python3 --version
		Python 3.10.12
		python3 -m venv .venv
		source .venv/bin/activate
		例如我这里的环境：(.venv) klp@klp-virtual-machine:~/test/tfmwork/trusted-firmware-m/build_s/api_ns$
		
	注意3：
	项目						说明
	postbuild.sh		必须在 build_s/api_ns 里跑，不是 common/scripts
	TFM_UPDATE.sh		必须在 postbuild 成功之后 再跑
	pip install -e .	在 trusted-firmware-m 根目录，编 S 前要有
	regression.sh		会擦 Flash、改 OB，不要每次烧录都跑
	
实际操作步骤：

	可以使用一键编译脚本:
	./buildtfm.sh

然后再烧录按照以下命令执行：	

	cd ~/test/tfmwork/trusted-firmware-m
	source .venv/bin/activate
	cd build_s/api_ns
	./regression.sh
	./TFM_UPDATE.sh
	最后注意：在stm32cubeprogrammer中把BOOT_UBE 改为 B4
